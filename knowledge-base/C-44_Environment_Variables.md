## 1. Rules (hand-written)

```
✅ NEXT_PUBLIC_*   → inlined into the browser bundle at BUILD: never a secret, never an internal
                     service URL (NEW-A), and changing one needs a redeploy
✅ API_GATEWAY_URL → server-only. The gateway is public (ADR-005), but the apps read it server-side
✅ JWT_SECRET      → the same value in every app and the auth service; refresh uses JWT_REFRESH_SECRET
✅ INTERNAL_SECRET → ≥ 32 chars; the services refuse to start without it
✅ PI_SANDBOX      → explicit "true"/"false", no default; Mainnet = false
✅ PI_API_KEY_<SOURCE> on payment-service, one per app slug (APP_SOURCE) — a missing one makes that
                     app's Mode-2 approve fail (C-12 §11); PI_API_KEY is the Hub's
❌ REFRESH_SECRET, PI_WEBHOOK_SECRET, PI_API_KEY_HUB — documented here until 2026-09-24; nothing reads them
```

## 3. Worth knowing

- **`@yasser172/tec-ui` reads `NEXT_PUBLIC_API_GATEWAY_URL`** (`src/constants/index.ts`). The
  gateway is public, so this leaks nothing — but it is the one `NEXT_PUBLIC_*` service URL left,
  in a package every app imports. Open as a decision, not a defect.
- `NEXT_PUBLIC_PI_APP_ID` is read by only five domain apps; the rest never needed it in code
  (Pi's `init` takes no app ID). Set it anyway — the Portal checklist asks for it.
