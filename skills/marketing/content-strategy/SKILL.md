# TEC Content Strategy

## Audience Segments

| Segment | Who | What They Want | Content Type |
|---------|-----|----------------|-------------|
| **Pioneer (User)** | Pi miner, 2019–2024 | Spend Pi on real things | Use case demos, "buy this with Pi" |
| **Builder (Dev)** | Pi app developer | Integration docs, SDK | Technical guides, ADR explanations |
| **Merchant** | Business owner | Sell products for Pi | Onboarding guides, revenue stories |
| **Investor/Analyst** | Web3 researcher | Platform metrics | Architecture overview, roadmap |
| **Pi Skeptic** | Web3-aware but cautious | Trust signals | Security audits, open source proof |

## Content Pillars

### Pillar 1: Education (40%)
```
"What is Pi Network?"
"How to pay with Pi on TEC"
"What can you buy with Pi?"
"Is TEC safe? (Open source + audit links)"
```

### Pillar 2: Product (30%)
```
"New feature: [feature name] is live"
"How merchants earn Pi on TEC Commerce"
"Your Pi assets: what you own and why it matters"
```

### Pillar 3: Community (20%)
```
"Pioneer spotlight: [merchant name] story"
"Community milestone: X Pi transacted"
"[Country] Pioneer meetup recap"
```

### Pillar 4: Technical Transparency (10%)
```
"How we handle your Pi payments (open source)"
"Our security audit results"
"Architecture update: what changed and why"
```

## Content Calendar Template

```
MONDAY    — Educational post (how Pi works on TEC)
WEDNESDAY — Product update or feature demo
FRIDAY    — Community highlight (merchant/creator story)
AD HOC    — Pi Network news response (price milestone, mainnet updates)
```

## Platform-Specific Format

| Platform | Format | Length | CTA |
|----------|--------|--------|-----|
| Pi Chat | Short + emoji | < 200 chars | Link to app |
| Pi Forum | Long-form | 500–1500 words | Tutorial with screenshots |
| Twitter/X | Thread | 5–10 tweets | Retweet CTA + app link |
| Telegram | Announcement | 100–300 chars | Deep link to feature |
| Blog (tecosystem.app) | SEO article | 1000–3000 words | Email signup + app link |

## Voice & Tone

```
✔ Confident but not hype (no "to the moon" language)
✔ Technical depth when writing for builders
✔ Simple language for pioneers (many are non-native English)
✔ Transparent about what's working and what's not
❌ No fake scarcity ("limited time only!")
❌ No price speculation
❌ No FUD about competitors
```
